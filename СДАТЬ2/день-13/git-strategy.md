# Стратегия ветвления проекта

## Дата: 05.10.2026
## Команда: ИСП-43
## Выбранная стратегия: GitHub Flow

## Обоснование
Проект ведёт один автор, релиз один — защита. Отдельный develop не нужен.
- `main` — то, что можно показать.
- `feature/*` — отдельное изменение.
- `bugfix/*` — исправление.
- `release/v1.0` — снимок перед тегом.

## Правила
1. Новая заметная правка начинается в ветке.
2. Сообщение коммита на русском и говорит, что изменилось.
3. В main попадает только то, что собирается типами.
4. Тег v1.0 ставится на main после слияния релизной ветки.

## Разрешённый конфликт

### Конфликт: constants.ts, предел ширины списка
- **Ветки:** feature/list-min и feature/list-max меняли соседние строки одного блока.
- **Причина:** обе ветки правили пределы LIST_WIDTH.
- **Решение:** оставить минимум 240 и максимум 560, оба имени констант.
- **Коммит:** см. историю `Разрешён конфликт пределов ширины списка`.

История смотрится так:

```
git log --oneline --graph --all
```

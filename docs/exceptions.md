# Исключительные ситуации

## Дата: 01.10.2026
## Команда: Кононов К.А., Артюхин А.Н., ИСП-43
## Система: мессенджер Rosemа

| № | Ситуация | Тип | Способ обработки |
|---|----------|-----|------------------|
| 1 | Отправка сообщения без сессии | Доступ | AuthError, сообщение «войдите» |
| 2 | Пустой текст сообщения | Валидация | ValidationError, кнопка не шлёт |
| 3 | Текст длиннее 4000 символов | Валидация | код TEXT_TOO_LONG |
| 4 | Занятое имя при регистрации | Бизнес-логика | USERNAME_TAKEN, форма остаётся |
| 5 | localStorage недоступен или переполнен | Системная | try/catch → StorageError, работа в памяти |
| 6 | Сбой сети при отправке | Сеть | состояние network_error, повтор retry |
| 7 | Неизвестная реакция | Валидация | REACTION_UNKNOWN |
| 8 | Повторное добавление контакта | Бизнес-логика | CONTACT_EXISTS |
| 9 | Профиль без userId | Данные | USER_REQUIRED, fallback пустой профиль |
| 10 | Битый JSON в storage | Данные | fallback на значение по умолчанию |

## Приоритеты

- Критические: 1, 5, 6 — приложение не падает.
- Важные: 2, 3, 4, 7, 8 — понятное сообщение.
- Желательные: 9, 10 — fallback.

## Стратегия

- Fail fast — пустые поля и неизвестная реакция сразу дают исключение.
- Graceful degradation — нет сети: сообщение в network_error, чат открыт.
- Fallback — битый JSON и пустой профиль заменяются значениями по умолчанию.

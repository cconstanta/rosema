# Отчёт о тестировании интеграции

## Дата: 25.09.2026
## Команда: Кононов К.А., Артюхин А.Н., ИСП-43
## Система: мессенджер Rosemа (не карта бронирования — модули перенесены на предметную область практики)

## Проверенные сценарии

| № | Сценарий | Результат | Комментарий |
| --- | --- | --- | --- |
| 1 | Регистрация пользователя | ✅ | `registerUser` + запись в storage, событие `user:registered` |
| 2 | Вход в сессию | ✅ | `login` поднимает `rosema.session` |
| 3 | Добавление контакта | ✅ | повтор одного имени отклоняется |
| 4 | Редактирование профиля | ✅ | тема и displayName сохраняются |
| 5 | Отправка сообщения | ✅ | draft → sending → delivered |
| 6 | Реакция на сообщение | ✅ | like/heart/fire/laugh, одна реакция на пользователя |
| 7 | Сообщение без сессии | ✅ | код `NOT_AUTHORIZED` |
| 8 | Данные после перезапуска модулей | ✅ | storage держит JSON (localStorage или память) |

Автопроверка: `npm test` / `node --test tests/*.test.js` — тесты регистрации, модели сообщения и интеграционный сценарий.

## Обнаруженные ошибки

- Прямых падений end-to-end нет.
- На учебной машине без браузерного localStorage используется память процесса — после закрытия Node данные сбрасываются. В браузере (`index.html`) ключи остаются.

## Выводы

Модули связаны только через `app.js` и шину событий, без импорта Chat из Contacts. Точка входа инициализирует сценарии дня 5. Для дня 6: unit-тесты на `addReaction` и `updateProfile`, плюс очередь офлайн-отправки.

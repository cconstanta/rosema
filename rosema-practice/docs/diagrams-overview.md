# Обзор диаграмм проекта Rosemа

Краткое описание одиннадцати диаграмм учебной практики. Подробный разбор — в отчёте `docs/Otchet_diagrammy_Rosema.docx`.

## Структурные

1. **Class Diagram** (`01_class.png`) — логическая модель предметной области: User, Contact, Chat, Group, Message, Reaction, Media, Call, Theme и связи между ними.
2. **Component Diagram** (`02_component.png`) — программная архитектура по слоям: клиенты (Web / Desktop / APK), сервисы (Auth, Chat, Media, Call), инфраструктура (Gateway, PostgreSQL, Storage, TURN).
3. **Deployment Diagram** (`03_deployment.png`) — физическое размещение: устройства пользователей и облачные узлы BaaS + медиа/звонки, протоколы HTTPS / WSS / UDP.

## Поведенческие

4. **Use Case** (`04_usecase.png`) — функции системы глазами Гостя, Пользователя и Администратора группы.
5. **Activity** (`05_activity.png`) — процесс отправки сообщения: ввод → валидация → сжатие медиа → сохранение → realtime-доставка.
6. **State Machine** (`06_state.png`) — жизненный цикл объекта Message: черновик → отправляется → доставлено / ошибка → прочитано / удалено.
7. **Sequence (Cooperation)** (`07_sequence.png`) — взаимодействие объектов в сценарии «отправить сообщение».

## Функциональные

8. **IDEF0 A-0** (`08_idef0_a-0.png`) — контекст: главная функция, входы I, выходы O, управление C, механизмы M.
9. **IDEF0 A0** (`09_idef0_a0.png`) — декомпозиция на A1 идентификация, A2 чаты, A3 сообщения, A4 звонок.
10. **DFD уровень 0** (`10_dfd0.png`) — система как один процесс и внешние сущности (пользователь, TURN, шлюз уведомлений).
11. **DFD уровень 1** (`11_dfd1.png`) — подпроцессы 1.0–4.0 и хранилища D1–D4.

Стек, заложенный в диаграммы: веб-клиент (PWA), оболочка Tauri, APK через Capacitor/TWA, backend на бесплатном BaaS (Supabase: Auth, Postgres, Realtime, Storage), звонки — WebRTC + TURN.
